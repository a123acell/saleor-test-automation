# Saleor 核心业务链路（实测通过）

> 环境：本地 Saleor 3.23.34 实例，`http://localhost:8000/graphql/`
> 验证方式：核心链路探针（本地保留，不随仓库发布）+ `scripts/validate_collection.py` 全量执行通过
> 最后验证：2026-10-02，19/19 请求通过

---

## 一、链路总览

一次完整的电商下单，需要 **11 个接口按固定顺序** 调用。顺序错了会直接失败（见第三节踩坑记录）。

| 序号 | 操作 | 类型 | 作用 |
| ---: | --- | --- | --- |
| 1 | `tokenCreate` | Mutation | 登录，获取访问 Token |
| 2 | `channels` | Query | 查询渠道，拿到下单用的 `channel` slug |
| 3 | `products` | Query | 查询商品，拿到 `variantId` 与价格 |
| 4 | `checkoutCreate` | Mutation | 创建购物车并加购 |
| 5 | `checkoutShippingAddressUpdate` | Mutation | 填收货地址 |
| 6 | `checkoutBillingAddressUpdate` | Mutation | 填账单地址 |
| 7 | `checkout` | Query | 查购物车详情，取可用配送方式与应付金额 |
| 8 | `checkoutDeliveryMethodUpdate` | Mutation | 选配送方式 |
| 9 | `checkoutPaymentCreate` | Mutation | 创建支付 |
| 10 | `checkoutComplete` | Mutation | 完成下单，生成订单 |
| 11 | `orders` / `order` | Query | 查询订单 |

> 顺序关键点：**5（收货地址）必须在 7（查配送方式）之前**，否则 `availableShippingMethods` 返回空数组。

## 二、各步骤要点

### 1. 登录 `tokenCreate`

```graphql
mutation TokenCreate($email: String!, $password: String!) {
  tokenCreate(email: $email, password: $password) {
    token
    refreshToken
    csrfToken
    user { id email isStaff }
    errors { field message code }
  }
}
```

- 变量：`email=admin@example.com`，`password=admin`
- 返回 `token`（约 716 字符）、`refreshToken`
- 后续请求通过 `Authorization: Bearer <token>` 携带

### 2. 渠道 `channels`

- 返回全部渠道。本环境 2 个：`default-channel`（USD）、`channel-pln`（PLN）
- `default-channel` 默认国家为 US，覆盖 CN 等 200+ 国家

### 3. 商品 `products`

```graphql
query Products($channel: String!, $first: Int!) {
  products(first: $first, channel: $channel) {
    totalCount
    edges { node { id name slug variants { id name sku pricing { price { gross { amount currency } } } } } }
  }
}
```

- 必须传 `channel`，否则取不到价格
- 下单需要的是 **变体 ID（`variants[].id`）**，不是商品 ID
- 本环境实测：29 个商品，首个为 Apple Juice，变体单价 1.99 USD

### 4. 创建购物车 `checkoutCreate`

```graphql
mutation CheckoutCreate($input: CheckoutCreateInput!) {
  checkoutCreate(input: $input) {
    checkout { id token totalPrice { gross { amount currency } } lines { id quantity } }
    errors { field message code }
  }
}
```

```json
{
  "input": {
    "channel": "default-channel",
    "email": "buyer@example.com",
    "lines": [{ "quantity": 1, "variantId": "<变体ID>" }]
  }
}
```

- 返回 `checkout.id` 和 `checkout.token`，后续操作都用 `id`
- `CheckoutCreateInput` 中只有 `lines` 是必填

### 5-6. 收货 / 账单地址

```graphql
mutation ($id: ID!, $shippingAddress: AddressInput!) {
  checkoutShippingAddressUpdate(id: $id, shippingAddress: $shippingAddress) {
    checkout { id shippingAddress { city country { code } } }
    errors { field message code }
  }
}
```

- `AddressInput` 所有字段在 schema 上都是**可选**，但实际有运行时校验：
  - **CN 地址会校验 `city` / `countryArea` 合法性**，填 `Shanghai` 会返回 `INVALID`
  - **US 地址可用**：`city=New York`、`countryArea=NY`、`postalCode=10001`
- 账单地址不能省，否则下单报 `BILLING_ADDRESS_NOT_SET`
- 服务端会规范化大小写，返回的 city 是 `NEW YORK`

### 7. 查询购物车详情 `checkout`

- 一次拿到三样东西：`lines[].id`（改数量/删除用）、`availableShippingMethods`、`availablePaymentGateways`
- **必须在填完收货地址之后调用**，否则 `availableShippingMethods` 为空

实测本环境可用配送方式 5 个：

| 配送方式 | 运费 |
| --- | ---: |
| Default | 0.00 USD |
| EMS | 34.20 USD |
| FedEx | 40.42 USD |
| UPS | 59.59 USD |
| DHL | 66.19 USD |

### 8. 选配送方式 `checkoutDeliveryMethodUpdate`

- 传 `deliveryMethodId`，来自上一步
- **会改变应付总额**（运费计入），后续支付金额要重新取

### 9. 创建支付 `checkoutPaymentCreate`

```json
{ "input": { "gateway": "mirumee.payments.dummy", "amount": "1.99", "token": "charged" } }
```

- 本环境启用了 Dummy 支付插件（两个渠道均启用）
- **Dummy 网关必须传 `token`**，否则报 `Token is required for mirumee.payments.dummy`
- `token` 取值可模拟不同支付结果：`charged`（成功）/ `refused`（拒绝）/ `pending`（待处理）
- `amount` 必须 ≥ 购物车应付总额，否则下单报 `CHECKOUT_NOT_FULLY_PAID`

### 10. 完成下单 `checkoutComplete`

- 成功后返回 `order`，含订单号、状态、金额
- 实测生成订单 #21，状态 `UNFULFILLED`，金额 1.99 USD
- 前置条件全部满足才能成功：商品行 + 收货地址 + 账单地址 + 配送方式 + 足额支付

## 三、踩坑记录（接口测试用例可直接复用）

> 下表的错误码与字段均由结算异常探针脚本实测确认（探针本地保留），
> 断言时请匹配 `code` 而非文案（文案会随版本变化）。

| # | 现象 | 错误码 | 字段 | 原因与解法 |
| ---: | --- | --- | --- | --- |
| 1 | 非法手机号被拒 | `INVALID` | `phone` | 地址校验会校验 `phone`；实测 `+86215550000` 不被接受，需用合法号码（如 `+12125550000`） |
| 2 | 可用配送方式为空 | — | — | 未先填收货地址；`availableShippingMethods` 依赖收货地址，返回空数组 |
| 3 | 创建支付失败 | `BILLING_ADDRESS_NOT_SET` | `billingAddress` | **必须先填账单地址**才能创建支付（比原记录更早触发，不必等到下单） |
| 4 | 下单失败 | `BILLING_ADDRESS_NOT_SET` | `billingAddress` | 未填账单地址直接下单同样报此错 |
| 5 | 下单失败 | `CHECKOUT_NOT_FULLY_PAID` | — | 未创建支付，或支付金额小于应付总额 |
| 6 | 创建支付失败 | `REQUIRED` | `token` | Dummy 网关必须传 `token` 参数 |
| 7 | 创建支付失败 | `PARTIAL_PAYMENT_NOT_ALLOWED` | `amount` | 不允许部分支付，`amount` 必须**等于**应付总额（不是「≥」） |
| 8 | 注册失败 | `REQUIRED` | `redirectUrl` | `accountRegister` 必须传 `redirectUrl` 用于拼确认链接 |
| 9 | 查询配送方式报错 | GraphQLError | — | `availableShippingMethods.price` 是 `Money` 类型，没有 `gross` 字段 |
| 10 | 查询不存在对象报错 | GraphQLError | — | `checkout(id:)` 主键是 UUID，传非法 UUID 会报 `badly formed hexadecimal UUID string`，需构造合法 UUID |
| 11 | 字段不存在返回 400 | — | — | 查询不存在的字段（如 `shop.currencies`）返回 **HTTP 400**，不是 200；正确字段为 `channelCurrencies` |
| 12 | 未授权访问 | GraphQLError | — | 本环境 `channels` 也需鉴权（`AUTHENTICATED_STAFF_USER`），并非公开接口 |
| 13 | 登录被限流 | `LOGIN_ATTEMPT_DELAYED` | — | 同一用户失败登录逐次指数封禁（1s/2s/4s…），登录成功即清零；测试需识别并等待解封 |
| 14 | refused 令牌仍可下单 | — | — | Dummy 网关只校验金额是否覆盖，不校验扣款状态，`refused` 也能 `checkoutComplete` 成功 |

## 四、接口返回的通用约定

- 业务错误（payload 内 `errors`）通常 HTTP **200**；字段/变量校验错误（顶层 `errors`）HTTP **400**
- 断言时**优先判断错误 `code` 与 `field`**，不要匹配文案
- 主键 ID 是 Base64 编码的全局 ID，形如 `Q2hlY2tvdXQ6...`，不要硬编码，需从响应中提取
- 金额字段是 JSON number，存在浮点误差（`1.99` → `1.9899999999999999911182158…`），
  比较前需归一化到两位小数（见 `common/money.py`）
